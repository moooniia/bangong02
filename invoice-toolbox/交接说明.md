# 发票工具箱交接说明

更新时间：2026-07-10

## 项目定位

这是一个本地 PC 发票整理工具，最终名称暂定为“发票工具箱”，归属品牌为“办公工具箱”。

核心目标不是单纯 OCR，而是把发票图片批量识别、人工核对、重命名归档、Excel 报表导出串起来。它应适合批量处理，所以默认必须保守：不确定就留给人工确认，不能为了填满表格而猜。

## 已确定的产品要求

- 软件名称：发票工具箱。
- 品牌：办公工具箱。
- 版本号：1.0.0。
- 软件 UI 使用办公工具箱网站的粉白品牌风格。
- 导出的 Excel 报表继续使用正式绿色表头和表格风格，不使用粉色。
- 去掉原版里的作者信息、免激活单机版等无关信息。
- 保留原版表格思路：归档链接、原始文件链接、统计行、便于人工追溯。
- 不确定字段必须留空或显示“待确认”，并用明显样式提示人工补充。
- 用户不需要看“异常原因”这类技术解释，所以导出表格里不要放“异常原因”列。
- 商品/服务等质量高的字段不能因为重构变空，优先沿用原有 OCR/解析能力。
- 每一条记录都可以打开右侧核对栏，不只限于待确认记录。
- 右侧核对栏不是常驻，点击记录时出现，用 X 关闭。
- 图片放大查看不能挡住填写区域，应支持边看图边填写。
- 图片查看要能缩放、拖动、旋转，打开和关闭要有自然的缩放动画。
- 版本信息页包含版权、版本号、办公工具箱链接，并带逐步放大/收回动画。
- 图标采用粉色底、白色票据符号方案。

## 关键安全逻辑

用户发现的核心风险是：发票图片中某块区域因为畸变或显示效果不好，OCR/解析可能把购买方信息误填到销售方，或者反过来。批量处理时这种错误非常危险，因为人工不一定能逐条发现。

因此现在的解析原则是：

- 购买方和销售方必须来自明确区域或明确上下文。
- 如果销售方区域不清楚，不能拿购买方字段去补。
- 如果购买方区域不清楚，也不能拿销售方字段去补。
- 如果税号校验不通过，要视为不可靠。
- 如果字段归属不明确，留空并标记待确认。
- “待确认”要在 UI 和 Excel 里都明显。

## Windows 当前卡点

在 Windows 上已经能打出约 102MB 的 `发票工具箱.exe`，说明依赖已经基本打进去了，不是之前 5MB 缺库包的问题。

但双击后会跳转到：

```text
http://127.0.0.1:8765/
```

然后页面打不开。

这说明程序至少执行到了打开浏览器这一步，但本机服务没有被浏览器正常访问。可能原因：

- 程序启动后内部服务线程异常退出。
- PyInstaller 打包后的资源路径仍有问题。
- Windows 防火墙/安全软件拦截本机 127.0.0.1 服务。
- 端口占用或服务未真正监听。
- `console=False` 导致错误被隐藏，看不到真实日志。

Mac 这边已经做过一个启动稳定性修正：

- 先启动服务线程。
- 确认端口可连接后再打开浏览器。
- 如果 8765 被占用，自动尝试后续端口。

但是 Windows 打包后仍打不开，所以下一步应在 Windows 本机看真实报错。

## 到 Windows 后建议第一步

先不要继续盲目改 UI，先定位为什么服务打不开。

建议在 Windows 上临时改成控制台版本打包，这样双击或终端运行时能看到错误。

方法一：直接用 Python 跑源码

```powershell
cd C:\Users\paz\Desktop\invoice-toolbox-project-fixed2
.\.venv-win\Scripts\python.exe app.py
```

然后看终端是否显示：

```text
发票工具箱已启动：http://127.0.0.1:8765
```

再手动打开：

```text
http://127.0.0.1:8765/
```

如果源码运行也打不开，问题在 app 启动或端口；如果源码能打开，问题在 PyInstaller 打包资源或隐藏依赖。

方法二：打一个控制台版 exe

在 `build/pyinstaller/invoice_toolbox.spec` 里临时把：

```python
console=False
```

改成：

```python
console=True
```

重新打包后从 PowerShell 运行：

```powershell
.\dist\发票工具箱.exe
```

这样能看到真实错误。

## 2026-07-10 Windows 修正记录

已修一个高概率启动问题：窗口版 PyInstaller 程序在 `console=False` 时可能没有可用的 `sys.stderr`，旧版 HTTP 请求日志直接写 `sys.stderr.write(...)`，浏览器访问首页时可能导致服务线程异常、连接被关闭。现在日志会安全写入 `发票工具箱.log`，并记录请求处理异常。

打包脚本也已增强：

- 支持 `-Console` 打控制台诊断版。
- 支持通过 `PYTHON_EXE` 指定 Python 路径。
- 找不到 Python 时会给出明确错误，不再只报 `py` 命令不存在。
- 双击启动时默认由 Windows 分配空闲端口，避免旧实例占用 `8765` 导致页面打不开。
- HTTP 服务在主线程运行，浏览器延迟打开，窗口版和控制台版行为一致。
